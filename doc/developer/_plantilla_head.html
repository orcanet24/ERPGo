Qué ocurre cuando ejecutas erpgow.exe, paso a paso, con el archivo responsable de cada tramo.

Arranque del servidor

  1. Parseo de flags — cmd/server/main.go lee --setup, --migrate, --install, --uninstall. Si alguno está, resuelve esa tarea y sale.
  2. Configuración — configs.EnsureEnv() (en configs/config.go) carga/crea el .env y devuelve un *Config con host, puertos, credenciales de BD y nivel de log.
  3. Logger — internal/logger.Init() abre logs/erpgow.log si LOG_ENABLED=1 y redirige también la salida estándar.
  4. Base de datos — infrastructure/persistence abre o arranca MySQL. Si no encuentra nada en 3306, sube el MySQL embebido en 3307. Crea la BD de control erpgo, aplica migraciones y siembra la empresa por defecto.
  5. Servidor HTTP — interfaces/web.NewServer(cfg, db) construye el mux, monta plantillas, registra rutas, arranca la cola de tareas y el orquestador de escrituras.
  6. Servidor gRPC — internal/pos/grpc_server.go escucha en GRPC_PORT (9095) para las cajas POS; cada terminal se autentica con su API key.
  7. Arranque efectivo — erpApplication.Start() lanza el gRPC en una goroutine y se bloquea en server.Start() (HTTP).
  8. Apagado — Ctrl+C / Stop del servicio Windows: primero se detiene el gRPC (cierra sesiones POS), luego el HTTP y por último se drenan bases y orquestadores.

Recorrido de una petición HTTP

  1. Middleware externo — cacheDefaultMiddleware fija Cache-Control y, en desarrollo, imprime un access log por cada request.
  2. Middleware CORS/headers — corsMiddleware añade X-Content-Type-Options, X-Frame-Options y, bajo /api/, los headers CORS.
  3. Auth y tenant — authMiddleware llama primero a attachScope (resuelve la empresa activa), luego valida sesión; sin sesión redirige a /login. Rutas públicas: /login, /api/pos/, /static/, /uploads…
  4. CSRF — ensureCSRFToken renueva el token en cada visita y enforceCSRF lo verifica en mutaciones.
  5. Handler — el mux enruta al handler correspondiente de interfaces/web/ (facturas, contabilidad, caja, usuarios…).
  6. Escritura transaccional — los endpoints que modifican datos pasan por internal/orchestrator: validación → journal en disco → cola → un único escritor aplica → correlativo confirmado → rastro en audit_log.
  7. Render — render.go pinta la plantilla de templates/ (cacheado) con datos del tenant.

Ruta de las cajas POS

  1. Terminal POS se conecta por gRPC al puerto 9095 usando su api_key.
  2. Interceptor — authInterceptor / streamAuthInterceptor en internal/pos/grpc_server.go valida el token antes de cualquier RPC.
  3. Servicio — se procesan Login, OpenTurn, ProcessSale, SyncOffline, GetAIAdvice… definidos en proto/pos.proto.
  4. Persistencia — cada operación escribe contra la BD de la empresa del terminal vía infrastructure/persistence y el orquestador.
  5. Offline-first — si el enlace cae, la venta se guarda localmente y SyncOffline la reintegra con su número fiscal cuando vuelve.

Núcleo y arranque

cmd/server/ núcleo

Punto de entrada real del programa. main.go (≈16 KB) parsea flags, carga config, prepara BD y levanta HTTP + gRPC. fieldkey.go resuelve claves de campos.

main.go · fieldkey.go

configs/ núcleo

Todo el acceso a variables de entorno. EnsureEnv() crea o lee .env y devuelve la configuración tipada del servidor.

config.go

embed.go (raíz) núcleo

Declara //go:embed de static/, templates/ y migrations/ para que el binario funcione en un solo archivo (con fallback disk-first en desarrollo).

embed.go · embed_test.go

internal/logger/ núcleo

Logger con niveles (debug/info/warn/error) configurable por LOG_ENABLED, LOG_LEVEL, LOG_FILE. Salida dual archivo + consola.

logger.go

internal/service/ núcleo

Registro como servicio de Windows (install/uninstall/run vía SCM). Se compila distinto en Windows y en el resto.

service.go · service_windows.go · manage_windows.go

internal/setup/ núcleo

Asistente de instalación interactivo (--setup): instala/conecta MariaDB, propone puertos, crea el super admin y los roles base.

wizard.go · mariadb.go · ports.go · backup.go · schema_check.go

Capa HTTP y lógica de negocio (aquí vive la mayor parte del código)

interfaces/web/ negocio

El servidor web completo: ~170 archivos Go con todos los handlers, la sesión, los middlewares, el render de plantillas, permisos, auditoría, multi-empresa y los módulos de negocio.

server.go · session.go · permissions.go · render.go · audit_chain.go · tenants.go · pos_api.go · ai_*.go · product.go · purchase.go · payroll.go …

internal/orchestrator/ negocio

La puerta única de escrituras. Toma una entrada, valida identificadores, escribe primero en un journal en disco, la encola y un único escritor la aplica en orden con correlativo e idempotencia. Impide perder ventas.

orchestrator.go · journal.go

internal/queue/ negocio

Cola de tareas en segundo plano con pool fijo, backpressure y volcado a disco cuando se satura. Alimenta trabajos asíncronos del ERP.

queue.go · context.go

internal/pos/ negocio

Servidor gRPC de las cajas POS: sesiones de terminal, turnos de caja, ventas, sincronización offline y consejos de IA. Arranca en el puerto 9095.

grpc_server.go · server.go · sync_server.go · ai.go

internal/security/ negocio

Primitivas criptográficas usadas por la aplicación (cifrado/descifrado de datos sensibles).

crypto.go

internal/upload/ negocio

Gestión segura de subida de archivos (logos, fotos de producto, facturas) con validación de tipo y tamaño.

manager.go · README.md

internal/webcheck/ negocio

Verificador de salud/consistencia de la parte web.

main.go

Persistencia y datos

infrastructure/persistence/ datos

Todo el acceso a MySQL/MariaDB: conexión, migraciones idempotentes con ledger, copia de plantillas de esquema, volcado con mysqldump, guardián de WAL, conversión SQLite→MySQL y un MySQL embebido opcional.

database.go · mysql.go · embedded_mysql.go · mysql_migrations.go · mysqldump.go · plantilla.go · walguard.go · sqlite_convert.go

migrations/ datos

Esquemas SQL organizados por dominio (inventario, ventas, contabilidad, HR, POS, CRM, IA) más el fiscal venezolano y los de sistema. Se aplican en orden alfabético.

schema.sql · schema_reconstruido_01…10 · schema_ve_fiscal.sql · schema_z_*.sql

data/ aux

Runtime: una base por empresa (data/empresas/) y el journal de escrituras del orquestador (data/escrituras/). No tocar a mano.

backup/ aux

Respaldos generados por el propio ERP (botón de respaldo y volcados programados).

Contratos e integración

proto/ datos

Definición gRPC del POS: pos.proto define el servicio bidireccional (stream + RPCs) y pos.pb.go / pos_grpc.pb.go son el código generado por protoc.

pos.proto · pos/pos.pb.go · pos/pos_grpc.pb.go

addons/ negocio

Sistema de extensiones de terceros (vía ERPGo-SDK, que está en ../ERPGo-SDK y se engancha con un replace en go.mod). Incluye el addon de ejemplo hello/.

hello/module.json · hello/web/index.html

fiscalprinteradapter/ datos

Adaptador de impresoras fiscales (Epson y similares) — comunicación por puerto serie con go.bug.st/serial.

examples/ aux

Ejemplos mínimos para desarrolladores de addons.

Presentación (frontend)

templates/ negocio

Plantillas Go HTML por pantalla: login, layout, listados, formularios, reportes, PDFs y el POS. Se sirven desde el cache de render.go.

layout.html · login.html · pos.html · product_form.html · report_engine.html · pos/…

static/ negocio

Assets servidos en /static/: CSS, JS de la aplicación, plugins (DataTables, Summernote, SweetAlert, toastr, jstree) e imágenes.

css/ · js/ · plugins/ · fonts/ · image/

assets/ tool

Copia de templates/, migrations/ y subidas usada por embed.go para empaquetar el binario único.

Despliegue, empaquetado y herramientas

instalador/ tool

Instalador de Windows con Inno Setup (ERPgo-Installer.iss, POS-Installer.iss), imágenes, binarios y Docker.

ERPgo-Installer.iss · POS-Installer.iss · docker/ · COMPILAR.bat

deploy/ tool

Configuración de despliegue: Caddyfile (proxy TLS) y certificados.

tools/ tool

Utilidades internas: limpiar (basura de tests en CI), estress y loadtest (pruebas de carga), firmar (firmado de binarios), plantillas.

cmd/docgen/ tool

Generador del manual del programador: escanea el código, construye el grafo de funciones e inyecta el modelo JSON en index2.html.

main.go · scan.go · graph.go · render.go · overlay.go

compilar-*.bat / Makefile tool

Scripts de compilación: versión protegida (obfuscar), lanzamiento Linux y targets de make.

.github/workflows/ci.yml tool

CI en dos carriles: -short en cada PR (minutos) y suite completa con MySQL cada noche (03:00 UTC).

Documentación y restos

doc/ aux

Documentación histórica: bitácoras, auditorías, planes, plantillas Excel de costos y el developer/ con este índice y el manual index2.html.

docs/ aux

Documentación operativa corta: planes de seguridad/Docker, resúmenes de ejecución y bitácoras recientes.

legacy/, protoc/, protoc_bin/ aux

Restos: binario de estrés antiguo y copias del compilador protoc usado para generar el código del POS.

bin/, uploads/, tmp_* aux

Salidas de compilación, archivos subidos por el usuario y temporales de pruebas. No son código fuente.

Bases de datos: esquema multi-empresa

BaseContenido
erpgoBD de control: catálogo de empresas, miembros, sesiones y usuarios login.
erpgo_<codigo>Una base por empresa: sus productos, facturas, contabilidad, etc. Se aísla por tenant.
erpgo_plantilla_*Plantillas de esquema usadas por los tests para clonar esquemas rápidamente.

Las migraciones de migrations/ se aplican con un ledger idempotente en infrastructure/persistence/mysql_migrations.go, de modo que re-ejecutarlas es seguro.
