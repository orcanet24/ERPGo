Crear un addon (guía + generador)

Un addon es un binario independiente con su manifest.json. El núcleo no se recompila: lo lanza, le entrega un token por loopback y sirve su pantalla en /mod/<id>. Este formulario crea la carpeta, los archivos y, si el servidor tiene Go, el binario.

Minúsculas, dígitos, guion y guion bajo; 2 a 39 caracteres. Será la carpeta y el prefijo de tablas y permisos.
Vacío = /<id>. No puede usar prefijos del núcleo (/module, /reports, /accounting…).
Clase de Font Awesome, por ejemplo fa-sticky-note-o.
Vacío = <id>_ver. Se concede en Configuración → Roles.
Opcional. Debe empezar por <id>_; genera un schema.sql con CREATE TABLE IF NOT EXISTS (sin DROP ni ALTER).
Opcional, separadas por comas. El núcleo crea un usuario MySQL de solo SELECT sobre estas tablas.
Opcional. El addon recibirá el aviso en /hooks/<evento> con el token de su sesión.
No sobrescribe addons existentes.
Paso a paso
  1. Elija un id: será la carpeta, el prefijo de sus tablas y el de sus permisos.
  2. Genere: se escriben manifest.json, main.go y, si pidió tabla, schema.sql.
  3. Compile: el ERP intenta go build. Si no hay Go en el servidor, el resultado trae el comando exacto.
  4. Abra y asigne el permiso: la pantalla se sirve en /mod/<id>; el permiso <id>_ver se concede en Configuración → Roles. El menú aparece al recargar.
  5. Lea datos: declare tablas en db_read; el núcleo entrega ERP_DB_READ_DSN y la base activa en X-ERP-DB.
  6. Escriba datos: no hay SQL libre. Cada verbo de db_write exige un handler en el núcleo (addonVerboRegistrar).
  7. Hooks: hooks_out solo acepta eventos que el núcleo emite.
  8. Firma: si existe addons/pubkey.ed25519, firme con tools/firmaraddon; en desarrollo, ADDONS_UNSIGNED=1.

Contrato completo: docs/PLAN-ADDONS.md. Ejemplo real: addons/hola/.
